|---|------|----------|

## 2. 決定事項
| 項目 | 方針 |
|------|------|
| 分類の方法 | ユーザーが自由にタグを付ける（あらかじめ決めたカテゴリーから選ぶ方式ではない） |
| データの持ち方 | `Tag` の表を作り、Snap と多対多でつなぐ。タグの表は全ユーザーで共通（同じ名前は 1 行） |
| 上限 | 1 つの Snap に 10 個、1 タグ 30 文字 |
| 受け渡しの形 | タグ名の配列（例：`["旅行", "カフェ"]`）。ID ではなく名前でやり取りする |
| 絞り込みの候補 | 自分の Snap に付いているタグだけ（他のユーザーのタグは見せない） |
| 入力の整え方 | 前後の空白を取る。空のタグと重複は、エラーにせず黙って捨てる |

### 元の計画（01）からの変更点
| 項目 | 01 の計画 | 実際 | 理由 |
|---|---|---|---|
| タグの文字数チェック | `ListField(child=CharField(max_length=30))` | `child=CharField(allow_blank=True)` にして、`clean_tag_names` で空白を取ってから数える | `max_length` だと空白を取る前の長さで数えてしまう。また、どのタグが長いのかをメッセージに入れたい |
| 作成・更新のレスポンス | 記載なし | 一覧と同じ形（`SnapSerializer`）で返す | フロントが、返ってきた Snap をそのまま一覧に足せる・置き換えられるようにするため。以前の更新は `{"comment": ...}` だけを返していた |
| 一覧の SQL | 記載なし | `select_related('file')` と `prefetch_related('tags')` を付けた | タグを返すようになり、Snap 1 件ごとに SQL が増える（N+1 問題）のを防ぐため。件数によらず SQL は 3 回 |
| 管理画面 | Tag を登録する | あわせて Snap の一覧にタグの列・絞り込み・左右のリストで選ぶ入力欄、Tag の一覧に Snap 数の列を付けた | B5 で、関係が正しいかを管理画面で確かめやすくするため |
| apiError.ts | 記載なし | `tags` の項目名と、入れ子のエラー（`{"tags": {"0": [...]}}`）に対応 | `tags` の要素ごとのエラーが `[object Object]` と表示されてしまうため |

## 3. 対応内容

### Backend
| ファイル | 内容 |
|---|---|
| `chocolatier_api/models.py` | `Tag(id, name=CharField(30, unique), created_at)` を追加（名前順）。`Snap.tags = ManyToManyField('Tag', related_name='snaps', blank=True)` |
| `chocolatier_api/migrations/0002_tag_snap_tags.py`（新規） | `tag` の表と、中間テーブル `snap_tags` を作る |
| `chocolatier_core/settings.py` | 上限値の定数 `MAX_TAGS_PER_SNAP = 10` / `MAX_TAG_LENGTH = 30` を追加 |
| `chocolatier_api/serializers.py` | 共通の処理 `clean_tag_names`（整える・チェック）と `set_snap_tags`（`get_or_create` で用意して `set()` で入れ替え）を追加。`SnapSerializer` に `tags`（`SlugRelatedField`）。作成・更新のシリアライザーで `tags`（`ListField`）を受け取り、レスポンスは `SnapSerializer` の形にした。更新では、`tags` を送らなければタグを変えない |
| `chocolatier_api/views.py` | `SnapList` に `?tag=` の絞り込みと N+1 対策。`TagList`（自分の Snap に付いているタグ名を重複なしで返す）を追加 |
| `chocolatier_api/urls.py` | `tags/` を追加 |
| `chocolatier_api/admin.py` | `TagAdmin` を追加。`SnapAdmin` にタグの列・絞り込み・`filter_horizontal` |

### Frontend
| ファイル | 内容 |
|---|---|
| `components/commons/TextInput/TextInput.tsx` | `onKeyDown` と `placeholder` を受け取れるようにした |
| `components/commons/TagInput/TagInput.tsx` / `.module.css`（新規） | Enter で追加・× で削除するタグ入力。日本語変換中の Enter は無視する。個数・文字数のエラーを表示する |
| `components/playground/TagInputTemplate/TagInputTemplate.tsx`（新規） | playground で TagInput を試す画面。`PlayGroundPage.tsx` にボタンを追加 |
| `utils/validators.ts` | 定数 `MAX_TAGS_PER_SNAP` / `MAX_TAG_LENGTH` と、`validateTagName` を追加 |
| `utils/apiError.ts` | `tags: 'タグ'` の項目名と、入れ子のエラーを平らにする `flattenMessages` を追加 |
| `pages/SnapshotPage/SnapshotPage.tsx` / `.css` | モーダルに TagInput。作成は `tags` を同じキーで繰り返し送り、更新は JSON の配列で送る。一覧の上に絞り込みのチップ（「すべて」＋ `tags/` の結果）。絞り込み中に、そのタグがない Snap を作った・タグを外したときは一覧から外す。選んでいたタグが候補から消えたら「すべて」に戻す |

## 5. 対象外
- タグ名の変更・タグの削除の画面（管理画面ではできる）
- どの Snap にも付いていないタグの自動削除（`tags` の表に残るが、候補には出ないので画面への影響はない）
- 複数のタグでの絞り込み（AND / OR）
- 大文字・小文字、全角・半角の同一視（「Cafe」と「cafe」は別のタグ）
- 自動テスト（`tests.py`）への移植：今回の確認は一時スクリプトで実施した。案件1・2 の分と合わせて、あとでまとめて移植する → 2026-10-04 に移植済み（`TagTests`）
