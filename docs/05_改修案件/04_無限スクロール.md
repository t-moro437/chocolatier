# 改修案件4：無限スクロール（cursor 方式のページング）

- 対象：Chocolatier（backend: Django + DRF / frontend: React + TypeScript）
- 作成日：2026-10-03
- 状態：完了（自動チェック・ブラウザ確認とも完了）
- 元の計画：[01_認証_バリデーション_タグ_無限スクロール.md](01_認証_バリデーション_タグ_無限スクロール.md) の「案件 4」
- 解説記事：[docs/03_articles/11_infiniteScroll.md](../03_articles/11_infiniteScroll.md)

## 1. 背景
| # | 課題 | 該当箇所 |
|---|------|----------|
| 1 | 一覧 API が自分の Snap を全件返すため、件数が増えると API も画面の表示も重くなる | `SnapList`、`SnapshotPage.tsx` |
| 2 | 一覧の `key` に配列の番号を使っており、先頭に投稿を足すと全部の要素が作り直される | `SnapshotPage.tsx` |

## 2. 決定事項
| 項目 | 方針 |
|------|------|
| 表示の仕方 | 無限スクロール（下までスクロールすると続きを読み込む） |
| ページングの方式 | cursor 方式（`CursorPagination`）。ページ番号方式は使わない |
| 1 回の件数 | 12 件 |
| 並び順 | 新しい順（`-created_at`） |
| 一番下の検知 | `IntersectionObserver`（scroll イベントは使わない） |

### 元の計画（01）からの変更点
| 項目 | 01 の計画 | 実際 | 理由 |
|---|---|---|---|
| 読み込み中にタグを切り替えたとき | 記載なし（「タグを切り替えたらリセット」のみ） | リクエストに番号を振り、最後に出したリクエストの結果だけを使う | 前のタグの結果があとから届いて、一覧に混ざるのを防ぐため |
| 読み込みに失敗したとき | 記載なし | 自動での読み込みを止める（`nextUrl` を `null` にする） | 目印が見えている間、失敗をくり返し続けるのを防ぐため |
| 監視の付け外し | 記載なし | 「続きがある・読み込み中でない」ときだけ監視する | 二重の読み込みを防ぐため。また、付け直した直後の通知で、画面が埋まるまで自動で読み込めるようにするため |
| 型の切り出し | `src/types/Snap.ts` に `Snap` | あわせて、一覧のレスポンスの型 `SnapPage` も置いた | `{next, previous, results}` の形を型で表すため |

---

## 3. 対応内容

### Backend
| ファイル | 内容 |
|---|---|
| `chocolatier_api/pagination.py`（新規） | `SnapCursorPagination(CursorPagination)`：`page_size = 12`、`ordering = '-created_at'` |
| `chocolatier_api/views.py` | `SnapList.pagination_class = SnapCursorPagination`。レスポンスが配列から `{next, previous, results}` に変わった。`?tag=` は `next` の URL に引き継がれる |

### Frontend
| ファイル | 内容 |
|---|---|
| `src/types/Snap.ts`（新規） | `Snap`（1 件）と `SnapPage`（一覧の 1 ページ分）の型 |
| `src/hooks/useInfiniteScroll.ts`（新規） | 一覧の一番下の目印が画面に入ったら、渡した関数を呼ぶフック。`enabled` が `false` の間は監視しない |
| `components/snap/SnapshotPanel/SnapshotPanel.tsx` | 自前の型 `Photo` をやめて、`types/Snap.ts` の `Snap` を使う |
| `pages/SnapshotPage/SnapshotPage.tsx` / `.css` | `nextUrl`・`loading` を管理する。最初の 12 件（初回・タグの切り替え時）と続き（目印が見えたとき）を、共通の `fetchPage` で取る。一番下に目印と「読み込み中...」を表示する。`key` を `snap.id` にした |

- 作成・更新・削除の処理は変えていない。`next` は「この投稿より古いもの」を表すので、手元の一覧の先頭に足したり、途中から消したりしても、続きの範囲はずれない。

## 4. 受入条件と確認結果

### 自動チェック（テスト用の一時 DB で確認）
| 確認したこと | 結果 |
|---|---|
| レスポンスが `{next, previous, results}` の形になる | ✅ |
| 14 件あるとき、最初は新しい順で 12 件。`next` に `?cursor=` が付く | ✅ |
| 1 ページ目を読んだあとに 1 件増やしてから続きを取っても、重複も抜けもない | ✅ 2 ページ目は残りの 2 件だけ |
| `?tag=旅行` で絞ると、`next` の URL にも `tag=旅行` が残る | ✅ |
| 絞り込んだまま最後までたどると、タグ付きの Snap だけが重複なく全部取れる | ✅ |
| TypeScript の型チェック・ESLint | ✅ エラー 0 件 |

### ブラウザでの確認
- [x] 最初に表示されるのは、新しい順で 12 件
- [x] 13 件以上あるとき、下までスクロールすると「読み込み中...」が出て続きが読み込まれ、重複や抜けがない
- [x] タグで絞り込んだ状態でも、無限スクロールが正しく動く
- [x] スクロールの途中で新規作成・削除しても、一覧が崩れない

- 投稿が少ないときは、確認する間だけ `pagination.py` の `page_size` を 2 にすると試しやすい（終わったら 12 に戻す）
