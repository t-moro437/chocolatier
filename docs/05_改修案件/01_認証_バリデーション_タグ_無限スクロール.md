# 改修案件：認証方式の見直し / バリデーション / タグ分類 / 無限スクロール

- 対象：Chocolatier（backend: Django + DRF / frontend: React + TypeScript）
- 作成日：2026-09-27

## 1. 背景
現状の実装には次の課題がある。

| # | 課題 | 該当箇所 |
|---|------|----------|
| 1 | JWT を localStorage に保存しており、XSS でトークンを盗まれる | `frontend/src/contexts/AuthContext.tsx` |
| 2 | Snap API に権限設定がなく、未ログインでも閲覧・作成・更新・削除ができる | `backend/chocolatier_api/views.py` |
| 3 | 一覧が全ユーザーの投稿を返す／作成時の user をフロントから送るため、なりすまし投稿ができる／更新・削除に持ち主チェックがない | `views.py`, `serializers.py`, `SnapshotPage.tsx` |
| 4 | 要件の「画像のみ・5MB まで」のチェックが未実装 | `serializers.py`, `FileInput.tsx` |
| 5 | 投稿を分類する手段がない | — |
| 6 | 一覧 API が全件を返すため、件数が増えると重くなる | `SnapList` |

## 2. 決定事項
| 項目 | 方針 |
|------|------|
| 認証トークンの保存先 | HttpOnly Cookie（CSRF 対策とセット） |
| 表示件数の制限 | 無限スクロール（cursor 方式のページング、12 件ずつ） |
| 分類 | ユーザーが自由にタグを付ける（多対多、1 投稿 10 個まで） |
| バリデーション | フロントとバックの両方で行う |

実施順：**案件 1 → 2 → 3 → 4**（各案件は単体で動作確認できる単位とする）

## 案件 1：認証（HttpOnly Cookie）と権限の修正

### Backend
- 新規 `chocolatier_api/authentication.py`
  - `CookieJWTAuthentication(JWTAuthentication)`：`request.COOKIES['access_token']` からトークンを検証する。DRF の `SessionAuthentication.enforce_csrf` と同じやり方で CSRF をチェックする
- `views.py` に追加
  - `CookieLoginView`：`TokenObtainPairSerializer` で検証し、`access_token` / `refresh_token` を HttpOnly・SameSite=Lax の Cookie にセットする。レスポンス本文にはトークンを含めない
  - `CookieRefreshView`：Cookie の refresh から新しい access を発行して Cookie を更新する
  - `LogoutView`：Cookie を削除する
  - `CsrfView`：`@ensure_csrf_cookie` で `csrftoken` を配布する
- `chocolatier_core/urls.py`：`token/`・`token/refresh/` を Cookie 版に差し替え、`logout/`・`csrf/` を追加する
- 権限の修正
  - `SnapList`：`get_queryset` で `user=request.user` に絞り、`order_by('-created_at')` にする
  - `SnapCreate`：`perform_create` で `serializer.save(user=request.user)` にする。`SnapCreateSerializer.fields` から `user` を削除する
  - `SnapDetail`：`get_queryset` を自分の Snap に限定する（他人の ID は 404）
  - 使われていない `FileUpload` view と URL を削除する（`FileSerializer` が未定義で壊れている）
- `settings.py`
  - `DEFAULT_AUTHENTICATION_CLASSES` を `CookieJWTAuthentication` に、`DEFAULT_PERMISSION_CLASSES` を `IsAuthenticated` にする（signup / login / refresh / csrf は `AllowAny`）
  - `CORS_ALLOW_ALL_ORIGINS` を廃止し、`CORS_ALLOWED_ORIGINS=['http://localhost:3000']`、`CORS_ALLOW_CREDENTIALS=True`、`CSRF_TRUSTED_ORIGINS=['http://localhost:3000']` にする
  - `CorsMiddleware` を `CommonMiddleware` より前へ移動する
  - Cookie 用の設定を追加する（Secure は DEBUG 時 False）

### Frontend
- 新規 `src/api/client.ts`：共通の axios インスタンス
  - `baseURL` は `process.env.REACT_APP_API_BASE_URL`（既定 `http://localhost:8000`）。3 箇所のハードコードを置き換える
  - `withCredentials: true`、`withXSRFToken: true`、`xsrfCookieName: 'csrftoken'`、`xsrfHeaderName: 'X-CSRFToken'`
  - レスポンスインターセプタ：401 のときは `/token/refresh/` を 1 回だけ呼んで元のリクエストを再送する。失敗したら `/signin` へ移動する
- `contexts/AuthContext.tsx`：localStorage を全廃する。起動時に `csrf/` → `user-info/` を取得して `user` をセットし、`login` / `logout` は API を呼ぶ
- 新規 `components/commons/ProtectedRoute/ProtectedRoute.tsx`：`user` がなければ `/signin` へ移動させる。`App.tsx` の `/snaps` をこれで包む
- `Header.tsx`：ログイン判定を `useAuth().user` に変える（コンポーネント名 `Layout` を `Header` に直す）
- `SnapshotPage.tsx`：`authHeaders` / `decodeJWT` / `user` の送信を削除して `client` を使う。PATCH は JSON で送る

### 受入条件
- ログイン後、Cookie に `access_token` / `refresh_token`（HttpOnly）があり、localStorage は空である
- 未ログインで `/snaps` を開くと `/signin` へ移動する。API を直接呼ぶと 401 が返る
- 他のユーザーの投稿は一覧に出ず、ID を指定して取得・更新・削除しても 404 になる
- access の期限が切れても、refresh が有効な間は操作を続けられる
- ログアウトするとヘッダー表示がすぐ切り替わる

## 案件 2：バリデーション

> 実装結果と、この計画からの変更点は [02_バリデーション.md](02_バリデーション.md) にまとめました。

### Backend（`serializers.py`）
- `SnapCreateSerializer.upload` を `ImageField` に変える（requirements に **Pillow** を追加する。requirements.txt は UTF-16 なので UTF-8 で保存し直す）
- `validate_upload`：5MB 以下、拡張子は jpg / jpeg / png / gif / webp に限る
- `comment`：最大 1000 文字（serializer 側で制限するので、マイグレーションは不要）
- エラーは DRF 標準の `{field: [messages]}` 形式で返す。`LANGUAGE_CODE='ja'` にして標準メッセージを日本語にする

### Backend（`views.py`）：サインアップ API の権限
- サインアップ画面は作らず、API は運用（Postman からのユーザー作成）のために残す
- `UserSignup` を `IsAdminUser`（スタッフ権限のあるユーザーだけ）にする。認証は CookieJWTAuthentication を使う
  - Postman では `token/` でログインし、`csrftoken` Cookie の値を `X-CSRFToken` ヘッダーに付けて呼ぶ

### Frontend
- `FileInput.tsx`：`accept="image/*"` を付け、選択時とドロップ時に形式・サイズをチェックしてエラーを表示する。ドラッグ中の枠表示が消えない不具合（`'dragover'` を `styles.dragover` に直す）も直す
- `SnapshotPage.tsx`：API の 400 エラーを、既存の `Message` コンポーネントでモーダル内に表示する
- `SignInPage.tsx`：未入力チェックと、ログイン失敗メッセージを追加する

### 受入条件
- 5MB を超える画像や、PDF などの画像以外のファイルは、フロントで弾かれる。API を直接呼んでも 400 になる
- 1001 文字以上のコメントは保存できず、エラーが表示される
- ログインに失敗すると画面にメッセージが出る
- サインアップ API は、未ログインなら 401、スタッフ権限のないユーザーなら 403 になり、管理者なら登録できる

## 案件 3：タグ分類（多対多）

> 実装結果と、この計画からの変更点は [03_タグ.md](03_タグ.md) にまとめました。

### Backend
- `models.py`：`Tag(id, name=CharField(30, unique))` を追加し、`Snap.tags = ManyToManyField(Tag, related_name='snaps', blank=True)` を作ってマイグレーション `0002` を作成する
- `serializers.py`：`tags` は文字列の配列で受け渡しする（`ListField(child=CharField(max_length=30))`、1 投稿 10 個まで）。作成・更新時に `Tag.objects.get_or_create` で紐付け、レスポンスは `tags: ["旅行", "カフェ"]` の形にする
  - 作成は multipart なので、`tags` は同じキーで繰り返し送る（DRF の ListField は `getlist` で受け取れる）
- `SnapUpdateSerializer`：`comment` と `tags` を更新できるようにする
- `SnapList`：`?tag=<name>` で絞り込めるようにする
- 新規 `TagList` view（`GET chocolatier_api/tags/`）：ログインユーザーが使っているタグだけを返す
- `admin.py` に Tag を登録する

### Frontend
- 新規 `components/commons/TagInput/TagInput.tsx`（+ module.css）：既存の `TextInput` を使い、Enter で追加・× で削除するタグ入力にする。既存の命名に合わせて playground に `TagInputTemplate` も追加する
- `SnapshotPage.tsx`：モーダルに TagInput を追加する。一覧の上にタグ絞り込みのチップ列（「すべて」と `tags/` の結果）を置く

### 受入条件
- 投稿時と更新時にタグを付け外しできる（1 投稿 10 個・1 タグ 30 文字まで）
- チップを押すと、そのタグの投稿だけが表示される。「すべて」で解除できる
- 絞り込み候補には、自分が使っているタグだけが出る

## 案件 4：無限スクロール

> 実装結果と、この計画からの変更点は [04_無限スクロール.md](04_無限スクロール.md) にまとめました。

### Backend
- 新規 `chocolatier_api/pagination.py`：`SnapCursorPagination(CursorPagination)`、`ordering='-created_at'`、`page_size=12`
- `SnapList.pagination_class` に設定する。レスポンスは `{next, previous, results}` に変わる（cursor 方式なので、途中で投稿が増えても重複や抜けが起きない。`?tag=` は `next` の URL に引き継がれる）

### Frontend
- 新規 `src/hooks/useInfiniteScroll.ts`：IntersectionObserver で、一覧の末尾に置いた目印要素を監視するフック
- `SnapshotPage.tsx`：`snaps`・`nextUrl`・`loading` を管理し、目印が見えたら `nextUrl` を読み込む。タグを切り替えたらリセットする。新規作成した投稿は先頭に追加し、`key` は `snap.id` にする
- 型 `Snap` を `src/types/Snap.ts` に切り出し、`SnapshotPanel` と共有する

### 受入条件
- 最初に表示されるのは新しい順で 12 件
- 13 件以上あるとき、下までスクロールすると続きが読み込まれ、重複や抜けがない
- タグで絞り込んだ状態でも、無限スクロールが正しく動く

## 対象外
- `/media/` の画像 URL そのものは、認証なしで見られる（Django の static 配信のため）。非公開にするなら別案件にする
- サインアップ画面の作成（作らないことに決定。サインアップ API は運用のために残す）
- サインアップ時の入力チェック（email の重複・パスワードの強さ）
- ログアウト時のトークン失効（blacklist）
- 同じ秒に同じ名前でアップロードしたときのファイル名の衝突（必要なら、ファイル名を uuid にする小修正を案件 2 に含める）

## 検証手順
1. `cd backend` → `venv\Scripts\activate` → `pip install -r requirements.txt` → `python manage.py makemigrations` → `python manage.py migrate` → `python manage.py test`
2. `python manage.py runserver` と、`cd frontend` → `npm start` を起動し、各案件の受入条件をブラウザで確認する（Cookie は DevTools > Application、ページングは Network タブの `?cursor=` で確認）
3. `npm test` が通る
